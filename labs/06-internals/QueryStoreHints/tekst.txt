🧠 Query Store Hints – inteligentne poprawki bez kodu

Od SQL Server 2022 pojawił się mechanizm, na który czekał każdy DBA, który musiał kiedyś „naprawiać” cudzy kod bez możliwości jego zmiany.
Query Store Hints to sposób, by wymusić wskazówki optymalizatora (hints) dla konkretnego zapytania – bez modyfikacji źródła aplikacji.

🔍 Jak to działa

Query Store od dawna gromadzi historię zapytań i planów w bazie danych.
Teraz można wykorzystać te dane do nadpisania zachowania optymalizatora dla konkretnego query_id.

Każde zapytanie ma swój query_id (hash tekstu + parametryzacja).

DBA może zarejestrować „hint” przy pomocy sp_query_store_set_hints.

SQL Server podczas kompilacji planu sprawdzi Query Store i dołączy wskazówkę z tej tabeli.

Dzięki temu nie trzeba już:

edytować procedur,

rekompilować kodu aplikacji,

stosować plan guides (które były toporne i trudne w utrzymaniu).

⚙️ Typowe zastosowania
Problem	Rozwiązanie przez Query Store Hint
Zbyt duże granty pamięci (puste CPU, duży tempdb)	OPTION (MAX_GRANT_PERCENT = 5)
Spille do tempdb przez zbyt małe granty	OPTION (MIN_GRANT_PERCENT = 2)
Wrażliwość na sniffing parametrów	USE HINT('DISABLE_PARAMETER_SNIFFING')
Niekonsekwentne plany po migracji wersji	QUERY_OPTIMIZER_COMPATIBILITY_LEVEL_150
Testowanie wpływu konkretnego hintu	FORCE ORDER, LOOP JOIN, HASH JOIN itd.
🧩 Architektura

Hints są przechowywane w:

sys.query_store_query_hints


Każdy wpis zawiera:

query_id – identyfikator zapytania,

hint_text – treść hintu (np. OPTION (MAX_GRANT_PERCENT = 5)),

is_enabled, reason, last_modified,

oraz informacje o błędach w przypadku niekompatybilności.

Mechanizm działa tylko dla zapytań, które są przechwytywane przez Query Store — dlatego baza musi mieć:

ALTER DATABASE [TwojaBaza] SET QUERY_STORE = ON;
ALTER DATABASE [TwojaBaza] SET QUERY_STORE (OPERATION_MODE = READ_WRITE);

⚖️ Najważniejsze zasady

Hint działa per query_id – zmiana tekstu lub parametrów = nowy query_id.

Hint obowiązuje dla wszystkich planów tego zapytania (nawet nowych).

Zmiana planu/kodu może „zgubić” dopasowanie – monitoruj skuteczność.

Query Store Hints są tymczasowym lekarstwem – nie zastępują indeksów ani refaktoryzacji kodu.

🧮 Jak to wygląda w praktyce
DECLARE @query_id bigint = 12345;

EXEC sys.sp_query_store_set_hints
     @query_id = @query_id,
     @value = N'OPTION (MAX_GRANT_PERCENT = 5)';

-- Sprawdzenie
SELECT * FROM sys.query_store_query_hints WHERE query_id = @query_id;


Wycofanie (rollback):

EXEC sys.sp_query_store_remove_hints @query_id = 12345;

📈 Obserwacja efektu

Query Store pozwala porównać statystyki przed i po:

avg_duration i avg_cpu_time w sys.query_store_runtime_stats

liczba wykonania (count_executions)

logical_reads jako wskaźnik zużycia I/O

To daje natychmiastową odpowiedź:
czy hint przyniósł poprawę, czy pogorszył sytuację.

💬 Podsumowanie

Query Store Hints to jak chirurgiczna ingerencja w plan zapytania – bez otwierania kodu.
Pozwalają DBA szybko stabilizować wydajność systemu i zrozumieć zachowanie optymalizatora.

„Nie każda optymalizacja wymaga zmian w kodzie. Czasem wystarczy znać rozmowę, którą prowadzi Query Processor z Query Store.”
